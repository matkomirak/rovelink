## 2) Implement the **Visual Mapping Editor** (core)

**Goal:** 3-pane editor with transforms, conflict policies, and live validation on samples.

**UI**

* **Left: Source tree**

  * Sample selector (dropdown of `items[]` from `/providers/:id/samples?type=Vm&limit=20`)
  * JSON tree (expand/collapse, copy path)
* **Middle: Rules table**

  * Rows: `source path` → `transforms[]` (chips) → `target field`
  * Optional **condition** (simple expression, e.g., `provider_kind == "proxmox"`)
  * **Conflict policy** dropdown per field: `provider-wins | cmdb-wins | manual-only | merge`
  * Add/Delete row, reorder rows
  * **Save** → `PATCH /api/pipelines/:id/mappings/:mapId { rules }`
  * **Load preset…** → picker (`/pipelines/presets` + `/pipelines/presets/:id`)
* **Right: Target preview**

  * Result of `POST /mappings/:mapId/test { sampleId }`
  * Show **adapter validation** errors/warnings inline (required/optional badges)

**Transforms (chips)**

* `lower`, `upper`, `title`, `strip`, `to_slug`
* `concat` (mini dialog for pieces)
* `map` (key→value table)
* `regex_extract` (pattern + group)
* `lookup_table` (select from rules.lookup_tables; quick edit dialog)
* `datetime_parse`, `pick_primary_ipv4`

**Acceptance**

* Create mapping with at least 5 fields and 1 child array (IPs or Interfaces).
* Test on 2 different samples → preview updates instantly.
* Save rules → pipeline version increments.
