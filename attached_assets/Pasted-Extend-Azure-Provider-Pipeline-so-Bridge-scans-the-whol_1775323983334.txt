Extend Azure Provider + Pipeline so Bridge scans the whole Azure subscription and imports not only VMs, but also Azure networking/infrastructure into NetBox
Goal

I want Azure discovery to go beyond just virtual machines.
Bridge must scan the whole Azure subscription and import:

Virtual Machines
Virtual Networks
Subnets
Network Interfaces
Private IP addresses
Public IP addresses
Availability Zones info
Resource Groups metadata where useful
Any VM-related Azure-specific attributes
Main rule

If an attribute already maps to a native NetBox field, use the native NetBox field.
If an Azure-specific VM attribute has no native NetBox field, create/store it as a NetBox custom field with prefix:

azure_vm_*

Example:

VM name → native NetBox VM name
Azure security type → azure_vm_security_type
VM generation → azure_vm_generation

5) NetBox custom field creation rules

When Azure provider sync runs, Bridge must ensure required NetBox custom fields exist.

Naming convention

All Azure VM custom fields must be prefixed:

azure_vm_*

Examples:

azure_vm_generation
azure_vm_architecture
azure_vm_security_type
azure_vm_image_publisher
Field type expectations

Use appropriate NetBox custom field types:

boolean for enabled/disabled
text for strings
integer for counts
select only if stable enums are worth it; text is acceptable for MVP
Idempotency
If custom field already exists, reuse it
Do not recreate or duplicate
If field is missing, create it automatically during housekeeping or provider sync

16) Important modeling rule

For Azure-specific data:

if there is a clear native NetBox field → use it
otherwise store as custom field with Azure prefix

For VM-specific extra attributes:

always use prefix azure_vm_

This is important because I want the full Azure VM detail preserved in NetBox, not only the generic VM core fields.
