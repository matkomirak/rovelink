## Goal

Introduce **pipelines** that map provider objects → CMDB objects with a **visual mapping editor**, **dry-run diffs**, **sync now**, and **versioning/rollback**.

## 1) DB Migrations (add if not already present)

## 2) Backend APIs

### Discovery & Samples

* `GET /api/providers/:id/object-types` → e.g., `["Vm","Interface","IP","Tenant","Site"]`
* `GET /api/providers/:id/samples?type=Vm&limit=20` → normalized sample objects (from your collector/normalizer)

### Pipelines

* `POST /api/pipelines` `{name, providerAccountId, cmdbAccountId}`
* `GET /api/pipelines/:id`
* `PATCH /api/pipelines/:id` `{name?, enabled?, schedule_cron?}`
* `POST /api/pipelines/:id/dry-run` → returns diff summary + detail (no writes)
* `POST /api/pipelines/:id/sync` → enqueues **bdp-sync** run; returns run id
* `GET /api/pipelines/:id/runs` → list runs

### Mappings

* `POST /api/pipelines/:id/mappings` `{sourceType, targetType}`
* `GET /api/pipelines/:id/mappings/:mapId`
* `PATCH /api/pipelines/:id/mappings/:mapId` `{rules}`
* `POST /api/pipelines/:id/mappings/:mapId/test` `{sampleId}` → single-object preview (transformed target + validation messages)

> Reuse the **NetBox adapter** for `validate()` + `upsert()`; add an **i-doit adapter** stub with `objectTypes()` + `validate()` to begin.

## 3) Rules Engine (MVP)

* **Rules shape** (already agreed): `target`, `matchBy`, `fields[]`, `children[]`, `conflicts{}`, optional `lookup_tables`, and transforms.
* Implement transforms: `lower`, `upper`, `title`, `to_slug`, `strip`, `concat`, `map{}`, `regex_extract`, `lookup_table`, `datetime_parse`, and helpers `pick_primary_ipv4`.
* **Conflict policies**: `provider-wins | cmdb-wins | manual-only | merge`.
* **Match/Upsert**: use `matchBy` (e.g., `custom_fields.ext_id`) for idempotent writes.

## 4) UI — BDP

### List `/pipelines`

* Columns: **Name · Provider · CMDB · Enabled · Last run · Next run · Actions**
* Actions: **Dry-Run | Sync Now | Edit | Disable**

### Create Wizard

1. **Select endpoints**: Provider (enabled), CMDB (enabled) → creates pipeline
2. **Type pairs**: pick source types → compatible target types → create `pipeline_mappings`
3. **Mapping editor** (3-pane):

   * **Source**: sample object tree (choose sample)
   * **Mappings**: rows `source path → transforms → target field` (+ conditionals, conflict policy per field)
   * **Target preview**: required/optional flags, type validation
   * **Save rules** → enable **Dry-Run**

### Dry-Run Modal

* Counts `{created, updated, unchanged, removed, errors}`
* Paged list with field-level changes (+ CSV export)

### Sync Now Modal

* Live log tail + final counts

### Versioning

* Increment `pipelines.version` on save.
* **Rollback** to a prior version (keep audit: who/when).
