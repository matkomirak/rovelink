## Providers (UI + API)

**UI**

* Table: **Name · Kind · Enabled · Last Sync · Next Run · Status**
* Row actions: **Sync Now**, **Test Connection**, **View Runs**, **Edit**, **Disable**
* “Add Provider” modal (kind → per-kind fields)
* Schedule editor (cron) with inline validator + “Next run …”

**API**

* `GET /api/providers`
* `POST /api/providers` `{kind,name,config,enabled,schedule_cron}`
* `PATCH /api/providers/:id`
* `POST /api/providers/:id/test`
* `POST /api/providers/:id/sync`
* `GET /api/providers/:id/runs?limit=50`

**Scheduler / Worker**

* Cron scheduler reads `provider_accounts.schedule_cron` and enqueues **provider-sync** jobs.
* Sync worker:

  1. Instantiate collector by `kind`
  2. `listVms()` → normalized array
  3. Map → **upsert to NetBox** (idempotent): VM/IPs/CFs/tags
  4. Update `external_objects` + record `sync_runs` counts `{created,updated,unchanged,removed,errors}`

**Proxmox config fields**

* `base_url`, `auth_method` (`password|api_token`), `username`, `password`, `token_id`, `token_secret`, `realm`, `verify_ssl`, optional include/exclude nodes.

**Proxmox test**

* Login (ticket or token) → `GET /api2/json/nodes` → return `{ok, nodes, version}`.

**Proxmox collector**

* Nodes: `GET /api2/json/nodes`; VMs per node: `/nodes/{node}/qemu`; optional agent IPs: `/qemu/{vmid}/agent/network-get-interfaces`.
* Normalize: `externalId="${node}-${vmid}"`, `name`, `provider="proxmox"`, `primaryIp4?`, `tags`, `node`.

```yaml
plugin: netbox.netbox.nb_inventory
api_endpoint: "{{ lookup('env','NETBOX_URL') }}/api/"
token: "{{ lookup('env','NETBOX_TOKEN') }}"
validate_certs: true

compose:
  patch_wave: >-
    {{ custom_fields.patch_wave
       | default(custom_fields.Patching.Wave, true) }}
  customer: "{{ tenant.name | default('') }}"
  os: "{{ platform.slug | default('') }}"
  role: "{{ device_role.slug | default('') }}"

keyed_groups:
  - key: patch_wave
    prefix: wave
    separator: "_"
  - key: customer
    prefix: customer
    separator: "_"
  - key: os
    prefix: os
    separator: "_"
  - key: role
    prefix: role
    separator: "_"
```

## Bridge Data Pipelines (BDP)

**UI**

* BDP List: **Name · Provider · CMDB · Status · Last run · Next run**; actions: **Dry-Run | Sync Now | Edit | Disable**

* **Create BDP** wizard:

  1. **Select endpoints**: dropdown Provider (enabled), CMDB (enabled) → creates `pipeline`.
  2. **Choose object type pairs**: Source types (from provider) vs Target types (from CMDB adapter) → creates `pipeline_mappings`.
  3. **Map attributes (visual editor)**:

     * Left: sample source object (from `collected_objects` samples)
     * Middle: mapping rows (source path → transforms → target field), with conditionals and conflict policy per field
     * Right: target preview (required/optional, validation errors)
     * Save rules; enable **Dry-run** button

* Actions on a BDP:

  * **Dry-Run** (no writes): show diff (created/updated/unchanged/removed) + field-level changes; CSV export
  * **Sync Now**: run with current rules; show live log + final counts
  * **Schedule** (cron) + “Next run …”
  * **Versioning**: increment `pipelines.version` on save; **Rollback** available

**API**

* Discovery/Samples:

  * `GET /api/providers/:id/object-types`
  * `GET /api/providers/:id/samples?type=Vm&limit=20`
  * `GET /api/cmdbs/:id/object-types`
* Pipelines:

  * `POST /api/pipelines` `{name,providerAccountId,cmdbAccountId}`
  * `GET /api/pipelines/:id`
  * `PATCH /api/pipelines/:id` `{name?,enabled?,schedule_cron?}`
  * `POST /api/pipelines/:id/dry-run`
  * `POST /api/pipelines/:id/sync`
  * `GET /api/pipelines/:id/runs`
* Mappings:

  * `POST /api/pipelines/:id/mappings` `{sourceType,targetType}`
  * `GET /api/pipelines/:id/mappings/:mapId`
  * `PATCH /api/pipelines/:id/mappings/:mapId` `{rules}`
  * `POST /api/pipelines/:id/mappings/:mapId/test` `{sampleId}`

**Rules JSON shape (concept)**

```json
{
  "target": "NetBox.VirtualMachine",
  "matchBy": ["custom_fields.ext_id"],
  "fields": [
    { "target": "name", "source": "vm.name" },
    { "target": "platform", "source": "vm.guest.os", "transforms": ["lower","to_slug"], "default": "linux" }
  ],
  "children": [
    { "target": "IPAddress[]", "source": "vm.interfaces[].ips[]", "fields": [{ "target": "address", "source": "." }] }
  ],
  "conflicts": { "platform": "provider-wins" }
}
```

## RTC Mapping Rules (ready to paste into rules editor)

### 1) **Proxmox.Vm → NetBox.VirtualMachine**

```yaml
target: NetBox.VirtualMachine
matchBy: [custom_fields.ext_id]
fields:
  - target: name
    source: vm.name
  - target: status
    source: vm.status
    transforms: [lower]
    default: active
  - target: tenant
    source: vm.tags.customer
    transforms: [strip, title]
    lookup_table: tenant_map
  - target: site
    source: vm.node
    transforms: [strip, upper]
    lookup_table: site_map
  - target: platform
    source: vm.guest.os
    transforms: [lower, to_slug]
    default: linux
  - target: custom_fields.ext_id
    expr: "concat('proxmox:', vm.node, '-', vm.vmid)"
  - target: custom_fields.ext_provider
    expr: "'proxmox'"
  - target: tags[]
    source: vm.tags[]
    transforms: [lower]
    merge: true
  - target: tags[]
    expr: "concat('provider/','proxmox')"
    merge: true
  - target: tags[]
    expr: "concat('node/', vm.node)"
    merge: true
children:
  - target: Interface[]
    source: vm.interfaces[]
    fields:
      - target: name
        source: name
      - target: mac_address
        source: mac
      - target: enabled
        expr: "true"
    matchBy: [mac_address]
  - target: IPAddress[]
    source: vm.interfaces[].ips[]
    fields:
      - target: address
        source: .
      - target: status
        expr: "active"
    attach:
      to: VirtualMachine
      relationship: primary_ip4_if_first
conflicts:
  platform: provider-wins
  tenant: cmdb-wins
  site: cmdb-wins
lookup_tables:
  tenant_map: { alpha: "Alpha Ltd", beta: "Beta Corp" }
  site_map: { PVE1: "PRG-DC1", PVE2: "PRG-DC2" }
```

### 3) **Azure.Compute.VirtualMachine → NetBox.VirtualMachine**

```yaml
target: NetBox.VirtualMachine
matchBy: [custom_fields.ext_id]
fields:

  - target: status

          deallocated: offline

  - target: site

    lookup_table: site_map
  - target: tenant
    source: vm.tags.customer
    lookup_table: tenant_map
  - target: platform
    source: vm.storageProfile.osDisk.osType

    default: linux

    expr: "concat('azure:', vm.id)"
  - target: custom_fields.ext_provider
    expr: "'azure'"
  - target: tags[]
    source: vm.tags[]
    transforms: [lower]
    merge: true
  - target: tags[]
    expr: "concat('provider/','azure')"
    merge: true
  - target: tags[]

  - target: IPAddress[]

    fields:
      - target: address
        source: .
      - target: status
        expr: "active"
    attach:
      to: VirtualMachine
      relationship: primary_ip4_if_first
conflicts:
  platform: provider-wins

  tenant: cmdb-wins
```

2. **Housekeeping**: Ensure schema creates CFs; Rebuild Group Cache feeds limit autocomplete.
3. **Inventory**: `keyed_groups` produces groups like `customer_Alpha`, `os_linux`, `wave_Wave2`, `role_db`.
4. **BDP**: Create pipeline (Provider+CMDB), pick object types, map fields with live validation; **Dry-Run** shows diffs; **Sync Now** writes and records run.
5. **RTC rules** above can be pasted into the rules editor and succeed on dry-run (with sample objects).
6. **Versioning** & **rollback** for pipeline rules; audit “who/when/version”.
