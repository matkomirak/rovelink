Task 1 — Fix automation inventory tenant isolation
--------------------------------------------------

File:

    server/routes/automation-inventories.ts

Problem:

Routes use direct DB queries without orgId filtering.

Examples:

    db.select().from(automationInventories)

and:

    where(eq(automationInventories.id, req.params.id))

These can expose or mutate automation inventories across organizations.

Required changes:

1. Add orgId to AuthRequest type:

    interface AuthRequest extends Request {
      user?: any;
      orgId?: string;
    }

2. All list routes must filter by orgId:

    where(eq(automationInventories.orgId, req.orgId!))

3. All single-object routes must filter by both id and orgId:

    where(
      and(
        eq(automationInventories.id, req.params.id),
        eq(automationInventories.orgId, req.orgId!)
      )
    )

4. All create routes must ignore client-provided orgId and set orgId from req.orgId:

    const { orgId: _ignoredOrgId, id: _ignoredId, ...safeBody } = validated;

    const [newInventory] = await db
      .insert(automationInventories)
      .values({
        ...safeBody,
        orgId: req.orgId!,
        createdBy: req.user?.id,
        updatedAt: new Date(),
      })
      .returning();

5. Default inventory logic must be org-scoped.

Unsafe:

    update automationInventories set isDefault=false where isDefault=true

Safe:

    update automationInventories
    set isDefault=false
    where and(
      eq(automationInventories.isDefault, true),
      eq(automationInventories.orgId, req.orgId!)
    )

6. Delete must be org-scoped:

    delete from automationInventories
    where and(
      eq(automationInventories.id, req.params.id),
      eq(automationInventories.orgId, req.orgId!)
    )

7. Refresh, preview, export, gate, default, and linked-source actions must first load the inventory by id + orgId.

8. Linked CMDB source lookup must also be org-scoped:

    where(
      and(
        eq(cmdbAccounts.id, inventory.sourceRef),
        eq(cmdbAccounts.orgId, req.orgId!)
      )
    )

or use:

    storage.getCmdbAccount(inventory.sourceRef, req.orgId!)

Acceptance criteria:

- Org A cannot list Org B automation inventories.
- Org A cannot read Org B automation inventory by ID.
- Org A cannot update/delete/refresh/export/preview Org B automation inventory.
- Org A cannot create a linked inventory using Org B's CMDB account.
- Setting default inventory only affects the current org.
- npm run check passes.
- npm test passes.


Task 2 — Replace manual role checks in automation inventories
-------------------------------------------------------------

File:

    server/routes/automation-inventories.ts

Problem:

The route uses exact role checks such as:

    if (userRole !== "admin") {
      return res.status(403).json({ message: "Admin role required" });
    }

This bypasses the central role hierarchy.

Required change:

Use the central role helper from:

    server/auth/roles.ts

Either apply middleware:

    requireRole("admin")

or use:

    hasRoleAtLeast(req.user?.role, "admin")

Expected behavior:

- admin can create/update/delete automation inventories.
- platform_admin can also create/update/delete automation inventories.
- operator cannot create/update/delete unless intentionally allowed.
- viewer cannot create/update/delete.

Acceptance criteria:

- No exact checks like userRole !== "admin" remain in automation-inventories.ts.
- platform_admin passes admin-level inventory routes.
- Tests cover platform_admin access.
- npm test passes.
