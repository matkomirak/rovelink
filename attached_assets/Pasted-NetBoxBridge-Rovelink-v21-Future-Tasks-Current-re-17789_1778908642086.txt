Task 1 — Scope provider stats by organization
---------------------------------------------

Files:

    server/routes.ts
    server/storage.ts

Problem:

GET /api/stats/providers currently calls:

    storage.getProviderStats()

The storage method uses:

    getProvidersUnsafe()

This returns provider stats across all organizations.

Required fix:

Change route:

    app.get("/api/stats/providers", authMiddleware, async (req: AuthRequest, res) => {
      const stats = await storage.getProviderStats(req.orgId!);
      res.json(stats);
    });

Change storage interface:

    getProviderStats(orgId: string): Promise<any[]>

Change implementation:

    async getProviderStats(orgId: string): Promise<any[]> {
      const providers = await this.getProviders(orgId);
      ...
    }

Also make provider runs inside stats org-safe:

    const lastRuns = await this.getProviderRuns(provider.id, 1, orgId);

Acceptance criteria:

- Org A only sees provider stats for Org A.
- Org B providers never appear in Org A stats.
- Add tests.
- npm test passes.
- npm run check passes.


Task 2 — Scope provider runs route by organization
--------------------------------------------------

Files:

    server/routes.ts
    server/storage.ts

Problem:

GET /api/providers/:id/runs calls:

    storage.getProviderRuns(req.params.id, limit)

without verifying provider ownership.

Required fix:

Route should first verify provider belongs to req.orgId:

    const provider = await storage.getProvider(req.params.id, req.orgId!);
    if (!provider) {
      return res.status(404).json({ message: "Provider not found" });
    }

Then fetch org-scoped runs:

    const runs = await storage.getProviderRuns(req.params.id, limit, req.orgId!);

Storage method should be:

    getProviderRuns(providerAccountId: string, limit: number, orgId: string)

Implementation should either:
- join syncRuns to providerAccounts and filter providerAccounts.orgId, or
- first verify provider with getProvider(providerAccountId, orgId).

Acceptance criteria:

- Org A cannot read sync runs for Org B provider ID.
- Existing provider run list still works for own org.
- Add tests.
- npm test passes.
- npm run check passes.

    server/storage.ts

Problem:

GET /api/inventory/suggest calls:

    netboxService.getSuggestions(query, storage)

The service uses:

    storage.getNetboxVmsUnsafe()

This can leak group names derived from another organization's imported VMs.

Required fix:

    getSuggestions(query: string, storage?: any, orgId?: string)

When orgId is present, use:

    storage.getNetboxVms(orgId)

Do not use getNetboxVmsUnsafe() for user-facing routes.

Acceptance criteria:

- Org A suggestions are built only from Org A VMs.
- Org B VM metadata does not appear in Org A suggestions.

Task 4 — Decide and fix group-cache housekeeping scope
------------------------------------------------------

Files:

    server/routes.ts
    server/services/netbox.ts
    server/storage.ts
    shared/schema.ts, if schema changes are needed

Problem:

POST /api/housekeeping/rebuild-groups-cache calls:

    netboxService.listAllGroups(storage)

The service uses:

    storage.getNetboxVmsUnsafe()

Then it clears and rebuilds the global group cache:

    storage.clearGroupCache()
    storage.addGroupCache(...)

This is global but only requires admin.

Required decision:

Choose one model.

Option A — org-scoped group cache:

- Add orgId to groupCache table.
- clearGroupCache(orgId)
- addGroupCache(orgId, item)
- listAllGroups(storage, orgId)
- Admin can rebuild only own org's cache.

Option B — global platform cache:

- Keep it global.
- Change route permission from admin to platform_admin.
- Clearly document it as a global platform operation.

Recommended:

Option A if group cache affects user-facing org data.
Option B if it is truly platform-wide.

Acceptance criteria:

- Normal org admin cannot clear/rebuild global cross-tenant cache.
- Either group cache is org-scoped, or endpoint is platform_admin only.
- npm test passes.
- npm run check passes.


Task 5 — Scope or restrict retry-last-failed housekeeping
---------------------------------------------------------

Files:

    server/routes.ts
    server/storage.ts

Problem:

POST /api/housekeeping/retry-last-failed calls:

    storage.getLastFailedSyncRuns()

This returns failed sync runs globally across all providers.

The route currently requires admin, so an org admin can potentially retry syncs for other orgs.

Required fix:

Choose one:

    storage.getLastFailedSyncRuns(req.orgId!)

Option B — platform-only:

    requireRole("platform_admin")

and document it as a global operation.

Recommended:

Option A for normal org admin behavior.

Acceptance criteria:

- Org admin only retries failed syncs for their own org.
- Platform admin behavior is explicit if global retry remains.
