Task 4 — Decide production signup and organization onboarding model
-------------------------------------------------------------------

Files:

    server/routes.ts
    shared/schema.ts
    README.md / PRODUCTION-HARDENING.md

Problem:

POST /api/auth/signup creates a viewer user without clearly assigning orgId.

Many tenant-scoped routes assume:

    req.orgId!

A user without orgId can produce broken tenant behavior.

Required decision:

Choose one model.

Option A — invite-only signup:

- Disable open signup in production.
- Require an invite token that includes orgId and role.
- New users are attached to the invite's organization.
- Expired/invalid invite returns 403.

Option B — create organization on signup:

- Signup requires organization name.
- Create a new organization.
- Create first user as admin of that organization.
- Set user.orgId.
- Return JWT with orgId.

Option C — platform-admin-only user creation:

- Disable public signup entirely.
- Only platform_admin can create users and assign orgId.

Recommended for this product:

Option A or C for enterprise use.
Option B only if you want self-service SaaS onboarding.

Acceptance criteria:

- Production users cannot exist without orgId unless they are platform_admin.
- JWT always includes orgId for tenant users.
- Routes that require org context fail cleanly with 400/403 if orgId is missing.
- Documentation explains the onboarding model.
- Add tests for signup/onboarding behavior.
- npm test passes.


Task 5 — Add org-context guard middleware
-----------------------------------------

Problem:

Many routes rely on:

    req.orgId!

This is okay only if auth always guarantees orgId for tenant users.

Required improvement:

Add middleware:

    requireOrgContext

Behavior:

    if user.role !== "platform_admin" and !req.orgId:
      return 403 or 400 with "Organization context required"

Use it on tenant-owned routes:

    projects
    providers
    CMDBs
    credentials
    job templates
    runs
    automation inventories
    pipelines
    inventory suggestions
    reports

Platform-global routes can skip it if they require platform_admin.

Acceptance criteria:

- Tenant routes fail cleanly if orgId is missing.
- No route crashes or queries with undefined orgId.
- platform_admin global routes still work.
- Tests cover missing-org JWT.
- npm test passes.
