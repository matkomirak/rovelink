# Rovelink: Fake Provider (generator) — Dev Brief

## 1) New provider kind

* **kind:** `"fake"`
* **variant (subkind):** `"proxmox" | "vsphere" | "azure" | "aws"`
* Purpose: generate deterministic, provider-shaped VM data for **discovery, samples, dry-run & sync**.

### Config JSON schema (server-side validate)

```jsonc
{
  "variant": "proxmox",            // enum: proxmox | vsphere | azure | aws
  "seed": 42,                      // integer -> deterministic output
  "vms": 200,                      // total VM count
  "tenants": ["Alpha","Beta"],     // used for tags/tenant mapping
  "sites": ["PRG-DC1","PRG-DC2"],  // or ["DC1","DC2"] for vSphere presets
  "clusters": ["C0","C1"],         // for vsphere; nodes for proxmox
  "nodes": ["pve1","pve2"],        // for proxmox
  "linux_pct": 70,                 // % linux vs windows
  "tags": {
    "customer": ["Alpha","Beta","Gamma"],
    "wave": ["Wave1","Wave2","Wave3"],
    "role": ["web","app","db"]
  },
  "nics_per_vm": { "min": 1, "max": 2 },
  "ips_per_nic": { "min": 1, "max": 2 },
  "ipv4_cidrs": ["10.50.0.0/16","10.60.0.0/16"], // pool for address gen
  "missing_ip_pct": 10            // % of VMs with no guest IPs (to test preflight)
}
```

> UI: show **variant** dropdown and a **“Basic / Advanced”** toggle. In Basic, only `variant`, `seed`, `vms`. In Advanced, expose the rest.

## 2) Normalized VM output (must match your RTC rules)

Emit **provider-shaped** objects so your presets work out of the box:

### A) `variant = "proxmox"`

```jsonc
{
  "vm": {
    "name": "alpha-web-001",
    "status": "running",                 // running / stopped
    "guest": { "os": "linux" },         // linux / windows
    "tags": { "customer": "Alpha", "wave": "Wave2", "role": "web" },
    "node": "pve1",
    "vmid": 101,                         // unique per node
    "interfaces": [
      {"name": "net0", "mac": "52:54:00:12:34:56", "ips": ["10.50.12.10/24"]}
    ]
  }

```

```jsonc
    "guest_full_name": "Ubuntu Linux (64-bit)",

    ],
    "guest_ip_addresses": ["10.60.3.23/24"]
  },
  "custom_attributes": { "customer": "Alpha" }
}
```

* Ext ID: `concat('vc:', vm.instance_uuid)`

### C) `variant = "azure"` (Compute VM shape)

```jsonc

    "name": "alpha-db-05",
    "location": "westeurope",
```

## 5) Presets & Pipelines (how you’ll use it)

You already have RTC rules. With Fake Providers, do:

### NetBox target

* Create Pipeline:

  * **Provider:** *Fake (Proxmox)* → **CMDB:** *NetBox*
  * Pair type: **Vm → NetBox.VirtualMachine**
  * **Load preset:** *Proxmox.Vm → NetBox.VirtualMachine*
  * **Dry-Run** → shows created/updated counts & diffs
  * **Sync Now** → writes VMs/IPs/tags/CFs into NetBox

### i-doit target

* Create Pipeline:

  * **Provider:** *Fake (vSphere or Azure)* → **CMDB:** *i-doit*
  * Pair: **Vm → i-doit.Virtual Server**
  * **Load preset:** *vCenter.VM → i-doit.Virtual Server* (or Azure variant)
  * **Dry-Run** → **Sync Now**

Then build an **Automation Inventory** from your NetBox CMDB (Linked), refresh, and use it in templates (limits like `customer_Alpha & os_linux & wave_Wave2 - role_db`).

## 6) Generator details (deterministic)

* Use a small seeded PRNG (e.g., mulberry32 or xorshift; no deps required).
* **Name pattern:** `<customer>-<role>-NNN`
* **OS distribution:** `linux_pct` split; Linux names: Ubuntu, Debian, RHEL; Windows: 2019/2022
* **MACs:** derive from seed+index → fixed OUI per variant (`52:54:00` for KVM-ish, `00:50:56` for vSphere feel)
* **IPs:** pick `ipv4_cidrs` → allocate subnets → per VM pick `/24` address; honor `missing_ip_pct`
* **IDs:**

  * proxmox: `vmid = base + i`, `node = nodes[i % nodes.length]`
  * vsphere: deterministic UUID (format with hex of index/seed)
  * azure: deterministic ARM IDs; include resourceGroup, location

Put common helpers in `server/services/fake-helpers.ts`.

## 9) Acceptance criteria

1. **Add Fake Provider (Proxmox)** with `{variant: "proxmox", seed: 1, vms: 100}` → **Test** returns `{ok:true}`.
2. **Discovery**: `/samples?type=Vm&limit=20` returns 20 proxmox-shaped items with deterministic names/IPs.
3. **Pipeline (Proxmox → NetBox)**: load preset **Proxmox.Vm → NetBox.VirtualMachine**, **Dry-Run** shows non-zero created; **Sync** writes into NetBox; re-run is idempotent.
4. **Pipeline (vSphere → i-doit)**: **Dry-Run** and **Sync** work with the i-doit preset (validate at least).
5. **Automation Inventory (Linked to NetBox)**: **Refresh** shows group counts and hosts; limits work in a template.
6. Changing `seed` or `vms` alters generated set; `missing_ip_pct` produces expected “missing IP” notes in dry-run.
