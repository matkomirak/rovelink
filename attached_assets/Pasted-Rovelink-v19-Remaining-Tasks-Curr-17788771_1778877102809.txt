Task 1 — Fix linked-CMDB validation before creating automation inventory
------------------------------------------------------------------------

File:

    server/routes/automation-inventories.ts

Problem:

POST /api/inventories inserts the automation inventory before validating that a linked CMDB sourceRef belongs to the current org.

Current behavior:

1. Insert inventory.
2. If type is linked, query CMDB by sourceRef + orgId.
3. If CMDB is not found, return 404.
4. But the inventory may already exist with an invalid/cross-org sourceRef.

Required fix:

Validate linked CMDB before inserting linked inventories.

Example flow:

    const orgId = resolveOrgId(req);
    const validated = insertAutomationInventorySchema.parse(req.body);

    if (validated.type === "linked") {
      if (!validated.sourceRef || !validated.sourceType) {
        return res.status(400).json({
          message: "Linked inventories require sourceRef and sourceType"
        });
      }

      const [cmdb] = await db
        .select()
        .from(cmdbAccounts)
        .where(
          and(
            eq(cmdbAccounts.id, validated.sourceRef),
            eq(cmdbAccounts.orgId, orgId)
          )
        );

      if (!cmdb) {
        return res.status(404).json({ message: "Linked CMDB not found" });
      }

      // only now insert inventory
    }

Alternative:

Wrap insert + linked CMDB validation + refresh in a database transaction and roll back on validation/fetch failure.

Acceptance criteria:

- Creating linked inventory with another org's CMDB ID returns 404.
- No dangling inventory row is created.
- Creating linked inventory with invalid CMDB ID returns 404.
- No dangling inventory row is created.
- Creating linked inventory with own org CMDB works.
- Add/update tests for this specific behavior.
- npm test passes.
- npm run check passes.


Task 2 — Add real route/integration tests for automation inventory isolation
---------------------------------------------------------------------------

Current tests:

tests/automation-inventory-isolation.test.ts is useful, but it uses in-memory route-logic mirrors instead of the real Express routes/database.

Required improvement:

Add integration coverage for real automation inventory routes.

Suggested file:

    tests/automation-inventory-integration.test.ts

Put it under:

    npm run test:integration

because it may require DATABASE_URL.

Test cases:

1. GET /api/inventories:
   - Org A only sees Org A inventories.
   - Org B inventories are not returned.

2. GET /api/inventories/:id:
   - Org A can read its own inventory.
   - Org A gets 404 for Org B inventory.

3. POST /api/inventories:
   - Client-provided orgId is ignored.
   - Created inventory uses req.orgId.
   - Cross-org sourceRef is rejected.
   - Cross-org sourceRef does not create a dangling row.

4. PATCH /api/inventories/:id:
   - Org A cannot update Org B inventory.
   - orgId cannot be changed through PATCH.

5. DELETE /api/inventories/:id:
   - Org A cannot delete Org B inventory.

6. POST /api/inventories/:id/refresh:
   - Org A cannot refresh Org B inventory.

7. Export/gate endpoints:
   - Org A cannot access Org B automation.yml.
   - Org A cannot access Org B blocked.json.
   - Org A cannot access Org B gate-stats.

Acceptance criteria:

- Integration tests pass with a real DATABASE_URL.
- Integration tests fail clearly without DATABASE_URL.
- Default npm test remains DB-free and passing.
