Task 1 — Fix linked inventory create behavior after external NetBox sync failure
--------------------------------------------------------------------------------

File:

    server/routes/automation-inventories.ts

Problem:

POST /api/inventories now correctly validates linked CMDB ownership before insert.

However, after insert it immediately calls NetBox:

    adapter.test()
    adapter.listAllVms()

If those calls fail, the route can return 400/403/500 after the inventory row was already created.

This creates confusing behavior:

    API response: create failed
    Database state: inventory exists

Required decision:

Choose one behavior and implement it consistently.

Recommended Option B:

Create the inventory once local validation passes.
If the first NetBox refresh fails, keep the inventory row but mark sync status as failed and return 201/202 with warning.

Example response:

    {
      "inventory": { ... },
      "sync": {
        "status": "failed",
        "message": "Failed to connect to NetBox: ...",
        "retryable": true
      }
    }

Alternative Option A:

Validate NetBox connection and fetch VMs before insert.
Only insert if external sync succeeds.

Alternative Option C:

Use a transaction and roll back the inventory row if external sync fails.
Be careful: external network calls inside DB transactions are usually not ideal.

Acceptance criteria:

- The API response matches database state.
- No route returns "create failed" while leaving a successfully created row without saying so.
- Failed initial NetBox sync is visible in inventory status/preview.
- User can retry refresh later.
- npm run check passes.
- npm test passes.


Task 2 — Validate linked source fields on PATCH
-----------------------------------------------

File:

    server/routes/automation-inventories.ts

Problem:

POST validates linked CMDB ownership before insert, but PATCH does not appear to validate sourceRef/sourceType if the inventory is changed to or remains type="linked".

A user should not be able to save:

    {
      "type": "linked",
      "sourceRef": "<cmdb id from another org>",
      "sourceType": "netbox"
    }

Required behavior:

Before updating an inventory, calculate the effective post-update values:

    effectiveType = req.body.type ?? existing.type
    effectiveSourceRef = req.body.sourceRef ?? existing.sourceRef
    effectiveSourceType = req.body.sourceType ?? existing.sourceType

If effectiveType is "linked":

    - sourceRef must exist
    - sourceType must exist
    - sourceRef must belong to a CMDB account in req.orgId

Example:

    if (effectiveType === "linked") {
      if (!effectiveSourceRef || !effectiveSourceType) {
        return res.status(400).json({
          message: "Linked inventories require sourceRef and sourceType"
        });
      }

      const [cmdb] = await db
        .select()
        .from(cmdbAccounts)
        .where(
          and(
            eq(cmdbAccounts.id, effectiveSourceRef),
            eq(cmdbAccounts.orgId, orgId)
          )
        );

      if (!cmdb) {
        return res.status(404).json({ message: "Linked CMDB not found" });
      }
    }

Also strip id and orgId from PATCH body:

    const { id, orgId, ...safePatch } = req.body;

Acceptance criteria:

- PATCH cannot change sourceRef to another org's CMDB.
- PATCH cannot change sourceRef to a non-existent CMDB.
- PATCH cannot change type to linked without sourceRef/sourceType.
- PATCH with own org CMDB works.
- Add tests.
- npm test passes.
