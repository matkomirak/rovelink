# Rovelink v0.1.0-alpha

**Govern first. Automate second.**

Status: early alpha; release preparation only. This document does not announce
a published release. The release tag is pending the public-release checks below.
Rovelink is not production-ready. APIs, schemas, and UI may change.

## Major Features

- Governance-first automation for infrastructure and MSP teams, with versioned
  blueprints, cached-object evaluations, findings, scores, and readiness.
- Git-backed Ansible project sync and playbook discovery from public HTTPS repos.
- Local and remote SSH Ansible execution through existing Automation GATE checks,
  with automation inventories, templates, run history, and encrypted SSH credentials.
- NetBox/CMDB cached VM browsing and governance without evaluation writeback.
- CustomerScope customer/environment boundaries, separate from application
  organizations, with NetBox tenant resolution and configurable governance policy.
- Cached provider inventory for fake/demo, Azure, and Proxmox sources. Provider
  customer candidates remain hints, not authoritative CustomerScope assignments.
- Manual provider-vs-CMDB VM drift comparison from API to Drift Reports UI, with
  matches, ambiguous/unmatched objects, findings, filters, and item details.

## Known Limitations and Safety Boundaries

- Not production-ready; use isolated environments and synthetic demo data.
- Proxmox normalized inventory is VM-only. Azure and Proxmox support is early.
  VMware/AWS/GCP normalized sync is not enabled; i-doit is outside the alpha pilot.
- No automatic remediation. Drift is analysis only: no CMDB/provider writeback,
  Governance readiness changes, or Automation GATE impact.
- Separate legacy CMDB pipelines and optional NetBox demo seeding can write to
  CMDBs. The drift/read-only inventory guarantees do not cover those operations.
- Governance and drift consume cached data. Matching is conservative and
  heuristic; names alone are not strong identity, and findings need human review.
- Blueprint enforce recommends blocking; Automation Inventory enforcement
  determines operational blocking. Default CustomerScope policy is visibility-only.
- Private/SSH Git repositories, SSH key passphrases, and AWX execution are outside
  the current MVP. APIs, schemas, and UI can change without migration guarantees.

## Verification and Release Gate

Task 17G validation passed: TypeScript check, all 500 default tests, production
build, and production dependency audit (zero vulnerabilities). The build retains
an existing PostCSS `from` option warning. Quick tracked-content searches found
no confirmed real credential; placeholders and synthetic test values are not
release failures. Gitleaks and TruffleHog were unavailable on PATH, so a dedicated
automated full-history scan has not been completed.

The Task 17F browser smoke test covered login/logout, navigation, fake cached
provider sync, cached CMDB/CustomerScopes, governance reports, manual drift runs,
filters/details, safe outage recovery, and automation page navigation. It did
not verify live Azure/Proxmox discovery, fresh-database setup, or a persisted
failed drift run. No automation execution or policy activation was performed.
