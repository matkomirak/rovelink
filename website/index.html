The problem

Your automation
doesn't know what it
shouldn't touch

  • ⚠VMs spin up in the cloud but never land in the CMDB — yet Ansible still reaches them.
  • ⚠Provider data and CMDB data drift apart within days. Nobody knows which version is true.
  • ⚠Ansible inventories built from providers include ungoverned, unassigned, or decommissioned machines.
  • ⚠No single platform connects provider discovery, CMDB governance, and automation in one flow.
The solution

A decision layer for workflows
routed through it:
govern first, automate second

  • ✓Rovelink combines configured reference and runtime data into an explainable readiness view.
  • ✓The pre-flight GATE returns allow, block, or unknown for supported action paths.
  • ✓Configured GATE checks filter local inventory targets. Reports and drift do not write back to the CMDB.
  • ✓One UI to manage providers, CMDBs, pipelines, and automation — with full run history.

The Automation GATE

A block is not
a failure.
It's the system working.

Rovelink evaluates supported actions before execution and returns an explainable allow, block, or unknown result. It is authoritative only for workflows that call the decision layer.

Known blockers stop the supported path. Missing or stale evidence remains unknown.

  • Role assigned in CMDB
  • automatable = true explicitly set

How it works

From cloud to CMDB
to Ansible — in one flow

1

Connect your providers

Connect supported sources. Azure and Proxmox normalized inputs are early alpha; VMware visibility remains planned.

2

Connect your CMDB

Use NetBox reference data to identify gaps, drift, missing ownership, and governance exceptions.

3

GATE runs — always

Supported workflows can request a pre-flight decision. Known blockers stop that path; incomplete evidence stays visible as unknown.

4

Ansible gets a clean inventory

Local inventory preparation applies configured checks. Enterprise adapters must bind decisions to actual targets; the existing AWX connector does not prove that enforcement.

Get started

Up and running
in under 5 minutes

One docker-compose file. No cloud account required. Works on any Linux host.

Option A — Docker (recommended)

# Clone the repo
$ git clone https://github.com/matkomirak/rovelink
$ cd rovelink
 
# Configure
$ cp .env.example .env
# Edit .env — set your secrets
 
# Start
$ docker compose up -d
 
✓ Running at http://localhost:5000

Option B — Bare metal (Ubuntu 22.04+)

# Clone
$ git clone https://github.com/matkomirak/rovelink /opt/rovelink
$ cd /opt/rovelink
 
# Legacy installer retired — follow UBUNTU-QUICKSTART.md
$ cp .env.example .env
# Provision local Postgres and set private .env values first
 
# Install, apply schema, and seed
$ npm ci
$ node --env-file=.env ./node_modules/drizzle-kit/bin.cjs push
$ node --env-file=.env --import=tsx server/seed.ts
# Start development server as documented in UBUNTU-QUICKSTART.md
 
✓ Credentials are displayed once during setup. Store them securely.
